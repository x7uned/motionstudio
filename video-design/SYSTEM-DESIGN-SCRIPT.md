# System Design: от сервера к системе · сценарий 60 секунд

Растущая соцсеть: сервер, балансировщик, кэш и реплики, шарды и файлы, очередь, резерв и наблюдаемость.

| Время | Экран | Озвучка |
|---|---|---|
| 00.00–05.50 | System Design без магии | Соцсеть растёт. Как менять её архитектуру без лишней сложности? |
| 05.50–11.80 | 01. Начинаем с простого | Начнём с сервера и базы. Человек открывает ленту, сервер читает записи. |
| 11.80–19.30 | 02. Распределяем нагрузку | Трафик растёт? Добавляем серверы. Балансировщик распределяет запросы между ними. |
| 19.30–26.00 | 03. Разгружаем чтение | Частые ответы держим в кэше. Реплики разгружают чтение, но могут отставать. |
| 26.00–34.20 | 04. Разделяем данные и файлы | Базе тесно? Делим данные на шарды. Файлы храним отдельно, раздаём через си-ди-эн. |
| 34.20–42.00 | 05. Убираем долгое ожидание | Видео обрабатывается долго? Ставим задачу в очередь. Воркеры работают в фоне. |
| 42.00–49.00 | 06. Готовимся к поломкам | При сбое переключаемся на запасной экземпляр. Нужны копии данных и проверки здоровья. |
| 49.00–60.00 | 07. Находим узкое место | Логи, метрики и трассировка помогают найти проблему. Добавляй сложность, только когда она убирает узкое место. |

Технические оговорки: Упрощённый учебный пример, не обязательная последовательность внедрения. Кэш может устаревать, асинхронные реплики отстают. Шардинг не заменяет резервные копии; CDN ускоряет доставку, не делает систему безотказной. Все схемы и графики условные.
