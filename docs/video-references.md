# Разборы видео

Подборка принимает **от одной до двадцати ссылок на конкретные Instagram Reels**. Ролики могут принадлежать разным авторам. С 2026-10-30 веб-интерфейса нет; всё делается командами `npm run studio -- …`:

- Apify подключает только пользователь, в своём терминале: `apify connect` (скрытый ввод → `.env.local`); проверка — `apify check`.
- Новая подборка: `refs add <reel-url>… --agent "<среда/модель>" --user-confirmed "<слова пользователя>" [--name «…»] [--step 0.5|1]`, затем `run <id>`. Запуск Apify — только с согласием пользователя (Free, предел $1).
- Список и подробности: `refs list`, `refs show <id>`; продолжить незавершённое — `refs retry <id>`; остановить — `cancel <id>` (заодно прерывает незавершённый запуск Apify).

Шаг извлечения кадров: 0,5 или 1 секунда (`--step`). Прежняя форма по умолчанию ставила 0,5 с; команда без `--step` берёт 1 с, поэтому шаг 0,5 с указывайте явно.

## Что сохраняется

- Исходный MP4, исходная ссылка и подпись.
- Транскрипция ElevenLabs Scribe v2 с таймкодами слов, если у видео есть аудио. Видео без аудиодорожки или распознанной речи можно разобрать визуально.
- Все извлечённые кадры с выбранным шагом и контактные листы по последовательным фрагментам. Длинный ролик не заменяется несколькими выборочными кадрами.
- Анализ каждого фрагмента и общий разбор видео.
- Сценарные функции и порядок сцен; текст на экране; композиция; движения камеры и объектов; свет и материалы; переходы; связь действия с распознанной речью.
- План реализации: предлагаемые инструменты, модели, текстуры и другие ассеты, шаги сборки каждой сцены и список неизвестных исходных данных.
- Каталог приёмов по подборке и ссылки на конкретные наблюдения.

## Последовательный анализ кадров

FFmpeg сохраняет изображения шириной 480 px с шагом 0,5 или 1 секунда. Последовательность делится на части по 30 кадров: примерно 15 или 30 секунд. Для каждой части строится контактный лист с абсолютными таймкодами и три увеличенных кадра для деталей. **Каждый извлечённый кадр попадает в один контактный лист и передаётся анализатору своей части.**

GPT-6.1 Sol xhigh обрабатывает каждую часть отдельно. Проверяется, что сцены покрывают фрагмент и не выходят за его временные границы. Затем общий технический план собирается из всех частей; список сцен сохраняется программно, чтобы итоговая сводка не выбросила части ролика. `refs show <id>` показывает статус каждого ролика; число проанализированных кадров и фрагментов записано в файлах разбора.

Это дискретный визуальный анализ. Модель не прослушивает звук; темп и паузы вычисляются по транскрипции. По кадрам можно обоснованно предположить движение камеры и способ построения сцены, но нельзя гарантированно восстановить исходную геометрию, точное фокусное расстояние, кривые анимации или оригинальный проект Blender/Three.js. Наблюдения, гипотезы и предлагаемый способ реализации должны быть различены в тексте.

## 3D и выпуск новых роликов

Разбор хранит предлагаемый способ сборки и подтверждённые наблюдения. Для 3D теперь подключён настоящий Three.js-рендер: отдельный режиссёр превращает сценарий и разбор в декларативный план моделей, света и камеры, после чего очередь выпускает MP4. Произвольный код не генерируется. Базовые модели доступны сразу; свои GLB/embedded GLTF добавляются командой `npm run studio -- models add <файл> --name «…» --rights «…»`.

Готовую 3D-подборку можно использовать в новом проекте: режим выбирается автоматически. Обычный 2D-шаблон не выдаётся за воспроизведение3D. Съёмка, экранные записи и сцены с отдельным монтажом по-прежнему требуют соответствующего рендерера. Исходная геометрия из видео не восстанавливается: используемые приближения записываются в плане и показаны на ревью. Подробности: [3D-рендер](3d-renderer.md).

Для поддерживаемых подборок разбор подключается при создании нового ролика: `npm run studio -- create --topic «…» --reference <id подборки>`. В проект сохраняется независимый снимок правил, планов сцен и примеров с SHA-256. Изменение исходной подборки не меняет старые проекты. Факты из референсов не считаются подтверждёнными источниками для новой темы: исследование темы остаётся отдельным этапом.

## Импорт и ограничения

- Apify получает только канонические URL выбранных Reels, не сканирует аккаунты. Tracking-параметры удаляются, одинаковые ссылки объединяются, больше 20 разных видео отклоняется.
- Импортируются только результаты, shortcode которых соответствует выбранным ссылкам. Результаты разных авторов разрешены.
- Ссылки на профили, чужие домены, URL с учётными данными, нестандартные порты и HTTP отклоняются до запуска Apify.
- Только Apify Free; максимум $1 на один запуск, без paid add-ons. Scribe и Codex используют свои лимиты. Шаг 0,5 с требует больше анализа и может значительно увеличить время обработки.
- Файл до 250 МБ, видео до 10 минут, суммарно до 45 минут на подборку. У недоступных или пропущенных ссылок сохраняется причина.
- Подборка считается полной, когда разобраны все выбранные ролики. Один успешно разобранный ролик уже может дать готовый результат; при недоступности других подборка помечается частичной.
- Очередь работает в движке студии (`npm run studio -- start`); чат и терминал можно закрыть. Для продолжения движок и компьютер должны работать.
- Повтор использует готовые видео, транскрипции, кадры, разборы частей и итоговые результаты. После неизвестного результата старта Apify новый запуск автоматически не выполняется. Повтор незавершённого Scribe разрешается только явной командой `refs retry <id>` и может ещё раз расходовать минуты.
- В базе сохранены внутренние имена таблиц authors/author_videos ради совместимости со старой версией. Старые записи, их снимки и проекты не переписываются. Бывшие маршруты `/api/authors` и `/api/video-references` удалены вместе с веб-интерфейсом; те же данные читают и пишут команды `apify` и `refs`.

## Файлы

`data/authors/<подборка>/<видео>/`:

- `video.mp4`, `audio.wav` (если есть аудио), `transcript.json`;
- `frames-500ms/` или `frames-1s/`, `frames.json`, `frames-part-NNN.jpg`;
- `part-NNN-analysis.json` и результаты анализатора частей;
- `production-analysis.json`, `analysis.json`, `REBUILD.md`.

В папке подборки сохраняются `profile.json` и `PROFILE.md` — каталог сцен и приёмов. Ключи остаются только в `.env.local` и не передаются Codex, не попадают в вывод команд или результаты анализа.
