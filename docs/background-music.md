# Фоновая музыка · обязательная подложка · 2026-10-20

Решение пользователя: в паузах речи видео звучали «пусто». Каждое новое видео студии **обязано** иметь
слышимую фоновую музыкальную подложку под всем фильмом — от первого кадра до заставки. Старый тон C3+G3
на уровне 0,009 на телефоне не слышен и музыкой не считается.

## Правило

1. Подложка берётся из сохранённой библиотеки `data/sound-packs/background-beds/<version>`. Текущая — **v2**:
   v1 без изменений (warm-pad, space-drone, lofi-pulse — предпочтительные; music-box, nature-air — сохранённые)
   плюс три подложки для explainer-роликов, выбранные пользователем 2026-10-20: pluck-curious, glass-arp, chip-soft.
2. Выбор делается один раз при создании проекта и фиксируется в `profile.musicBed`; перерендер и правка
   изображения сохраняют ту же подложку. Правила по теме (`src/lib/music-beds.ts`, первое совпадение):
   космос → space-drone; «что если» с Землёй → space-drone; история/изобретения → warm-pad;
   цифровое (QR, интернет, пиксели, данные, телефоны) → chip-soft; математика/сигналы/алгоритмы → glass-arp;
   быт (еда, сон, утро) → lofi-pulse; иначе — равновероятно одна из pluck-curious / glass-arp / chip-soft.
   music-box и nature-air автоматически не выбираются — только явным `--music`.
3. Подложка строится процедурным генератором ровно под измеренную длительность фильма (часы сцен 30 fps),
   с плавным входом и выходом; один непрерывный слой, без перезапуска на главах.
4. Голосовой PCM-мастер не меняется и не растягивается. Подложка приглушается под речью и поднимается в паузах
   (стартовые уровни из демо: пауза −8 dB, речь −15 dB от файла −20 LUFS; атака 0,12 с, восстановление 0,7 с).
   Общая нормализация микса прежняя (−16 LUFS, −1,5 dBTP); эффекты и правило 3 с не меняются.
   К началу заставки подложка плавно (1,2 с) уходит в тишину: под заставкой звучат только её cue.
5. Новые подложки — только новой версией пакета (`v2`…) или новым id; опубликованные файлы v1 не переписываются.
   Скачанная музыка допустима только с записанным источником и лицензией, без Content ID.
6. Старые проекты, сохранённые шаблоны и tech-story/v1 не переписываются задним числом.

## Реализация · cue sheet v9 · 2026-10-20

- Создание (`createProject`): те же новые проекты, что получают заставку (исследованные темы и illustrated-scene/v2),
  получают `profile.musicBed`; снимок генератора и `bed.json` с SHA-256 лежит в `data/projects/<id>/music-bed/`.
  tech-story/v1, illustrated-scene/v1 и готовые планы остаются без музыки, если редактор не указал `--music <bed>`.
- Воркер перед сведением строит подложку генератором из снимка ровно на длину часов сцен, приглушает под
  `narration.wav` и пишет `music-bed.f32` (float32 stereo 48 кГц, SHA-256 в cue sheet). Правка изображения
  делает то же без TTS.
- Cue sheet v9 = v8 + `musicBed` и `backgroundGain: 0`. Без выбранной подложки cue sheet остаётся v8 байт в байт,
  `scripts/remix.py` смешивает старый тон и даёт прежние файлы (проверено сравнением на копии 06ff2ae5).
- `remix.py` проверяет хеш и длину подложки, сводит premix в стерео (голос и эффекты по центру) и пишет
  `musicBed` с измеренным RMS в `sound-mix-report.json`.
- Наблюдение: стерео-premix после loudnorm звучит примерно на 0,9 dB громче прежнего моно-микса
  (копия 06ff2ae5: −16,4 против −17,25 LUFS, пик −1,49 dBTP) — внутри допуска проверки экспорта.
- Старые проекты автоматически музыку не получают; добавить её в существующий проект — отдельное явное решение.
- Проверено 2026-10-20: `npm run check`, `npm test` (вкл. `scripts/music-beds.test.ts`), сквозной прогон
  снимок → генерация → приглушение → v9 → `remix.py` на копии 06ff2ae5. Ещё не выполнены: `npm run build` и
  реальный create→render→review — после перезапуска воркера (до перезапуска работающий воркер использует старый код
  и новые проекты сводятся без музыки, хотя `profile.musicBed` уже записан).

## Аранжировка по сюжету · background-beds/v3 · cue sheet v10 · 2026-10-21

Пользователь прослушал демо `work/vizavi-demo` и одобрил музыку как композицию и работу эффектов
(«отличная работа с музыкой… с эффектами отличная»); камеру из того же демо не принял — она в студию не переносится.
Новые проекты берут **v3**: те же тембры, но подложка строится под каждый фильм из его плана, а не петлёй.

- Правила (`src/lib/music-arrangement.ts`, детерминированно, без отдельной модели): вступление тонкое, грув со 2-й главы
  (не позже 10 с); главы меняют гармонию; warn-выноска режиссёра → провал (удар + падающие ноты, мелодия и ударные уходят)
  до ok-выноски, следующей главы или 7 с; ok после провала → подъём с колокольчиками; другие ok → колокольчики;
  крупное слово → звон; финальный аккорд — на последней смысловой главе (не позже чем за 3 с до заставки), темп
  в пределах ±6 % подгоняется, чтобы вход грува и аккорд легли на долю; дальше хвост, к заставке музыка уходит.
  Акценты не ближе 2,5 с (провал → его подъём — 1,2 с), сильнее побеждает, слабые не сдвигаются, а отпадают.
- Громкость: аранжировка измеряется при каждом рендере (ffmpeg loudnorm) и выводится к −20 LUFS; под речью −12 dB,
  в паузах −8 dB — уровень одобренного демо (у v2 под речью −15).
- Эффекты: cue sheet v10 = v9 + `musicBed.arrangement` (bpm, провалы, акценты, SHA-256 `music-bed/arrangement.json`);
  блип `highlight` в ±0,35 с от музыкального акцента не звучит, остальные эффекты, правило 3 с и заставка без изменений.
- Снимок проекта: `music-bed/arranged.mjs` + `bed.json` (SHA-256), при рендере — `arrangement.json`. v2-проекты
  остаются на v2/v9, проекты без подложки — v8 байт в байт.
- nature-air в v3 статичная; music-box аранжируется, но выбирается только явно.
- Проверено: `npm run check`, `npm test` (203), сквозной путь снимок → аранжировка → генерация → замер → приглушение →
  v10 → `remix.py` на копиях 401596f0 (QR, chip-soft: 9 акцентов, 3 провала, −16,3 LUFS / −1,44 dBTP) и 06ff2ae5
  (Солнце, space-drone: 7 акцентов, −16,4 LUFS / −1,5 dBTP); MP4 для прослушивания — `work/background-music/arranged-v3/`.
  Реальный create→render→review через воркер — после его перезапуска (работающий воркер ещё на старом коде).

## Одиночные акценты · background-beds/v4 · правила аранжировки 2 · 2026-10-21

Пользователь услышал в готовых роликах повторяющийся тройной звон «готово» без видимой причины: это был акцент
«подъём» v3 — три колокольчика вверх с шагом 0,45 с — на **каждой** зелёной выноске (в QR-ролике 4 раза, в
тоннеле 4). Решение пользователя: звук должен соотноситься с действием на картинке и не быть тройным.

- Новые проекты берут **v4** (`MUSIC_PACK`). Генератор отличается от v3 только блоком акцентов: каждый акцент —
  один звук ровно на событии картинки (провал — удар с одной падающей нотой; подъём — один колокольчик; крупное
  слово — один звон; финальный аккорд — аккорд).
- Правила 2 (`buildArrangement(input, 2)`, выбираются по пакету v4): подъём — только там, где зелёная (ok) выноска
  закрывает провал от красной (warn), то есть на видимом решении проблемы. Обычные зелёные выноски получают свой
  UI-блип появления (cue sheet), а не музыкальный акцент. Arrangement пишет `version: 2`.
- v3-проекты остаются на правилах 1 и своём снимке генератора байт в байт; пакет v3 не изменён (тест сверяет).
- Прослушки v4: `data/sound-packs/background-beds/v4/audio/*-qr-arrangement.m4a`. Для QR-ролика: звон 2,2 с,
  провалы 29,2 / 53,4 / 72,9 с, один подъём 55,3 с («TWO SPARE ONES»), аккорд 86,5 с.
- Подложку в существующий проект добавляют только по явной просьбе редактора:
  `node --import tsx work/director-tools/add-music.mts <id> <bed> "<слова>"` (старый MP4 — в `versions/`).

## Петля · background-beds/v5 · 2026-10-22

Для роликов с явной концовкой-петлёй (`create … --ending loop`, `docs/illustrated-renderer.md`, раздел «Петля») музыка идёт через стык без затухания и целым числом тактов.

- Пакет v5 = v4 + режим `arrangement.loop`. Без `loop` генератор выдаёт тот же файл, что v4, байт в байт.
- v5 выбирается только для петли; прочие новые проекты остаются на v4.
- Аранжировка (`buildArrangement(…, 2, {loop:true})`): правила акцентов те же (2), но:
  - темп подогнан к целому числу тактов на фильм;
  - грув с первой доли;
  - нет финального аккорда;
  - последний такт — доминанта, она ведёт в первый аккорд следующего круга.
- Генератор играет три прохода и вырезает средний. Его первые 0,5 с плавно переходят из настоящего продолжения конца, поэтому хвосты нот и реверберации звучат через стык.
- `duckBed(…, loop)`: без затуханий в начале и в конце. Огибающая приглушения начинает с того состояния, которым заканчивается.
