# Агентный режим · agent/1

Решение пользователя (2026-10-19): студией управляет чат-агент (Claude Code или Codex/ChatGPT) по навыку `.agents/skills/motion-studio/SKILL.md`. Веб-интерфейс остаётся витриной на той же базе: смотреть, слушать, одобрять.

## Кто думает
В агентном проекте (`profile.production.agentMode={version:1,declaredAgent}`) все LLM-роли выполняет **ведущий агент в чате**: планирование поиска, исследование, рассказ, редактор, фактчек, разметка, голосовые указания, визуальная концепция, сценограф, motion-режиссёры 2D/3D/netcode/illustrated/isometric, ревью кадров итогового MP4, а также разборы Reels и стиль автора. Студия не запускает Codex/Claude CLI. Детерминированная часть не меняется: Tavily Search+Extract, валидация JSON Schema/Zod, ElevenLabs TTS и Scribe, звук, Remotion, FFmpeg, измерение файла, OCR.

Модель ведущего агента — **самоотчёт** (`--agent "claude-code/claude-opus-5-5"`), студия её не проверяет и пишет `verified:false` в `progress.json`, `pipeline.json`, контексты режиссёров и `approval.json`. Легаси-проекты и проекты из UI по-прежнему используют GPT‑6.1 Sol / Claude Opus 5.5; их дескрипторы, промпты и кэши не изменились.

## Скилл, движок и UI (решение пользователя 2026-10-21)
Студия — скилл для любого чат-агента с настройками: `.agents/skills/motion-studio/SKILL.md` — единая точка входа (Claude Code, Codex и другие), Next.js не нужен.
- **Движок** (`scripts/worker.ts`, один процесс, один `data/worker.lock`): `npm run studio -- start` (в фоне, журнал `data/logs/engine.log`), `start --foreground`, `stop` (отказывает при выполняющихся задачах; `--force` — по согласованию), `status`. В Claude Code движок запускается в терминале пользователя: в песочнице Bash нет входа Tavily. `run` подсказывает запуск или запускает движок сам при `engine.autostart=true`.
- **UI** — по просьбе человека: `npm run studio -- ui [--open]` поднимает Next.js на `127.0.0.1:<ui.port>` и печатает адрес; `ui stop`. `npm start` оставлен для совместимости: UI + движок; если движок уже запущен отдельно, запускается только UI, а остановка движка не закрывает UI.
- **Настройки** — `studio.config.json` + `npm run studio -- config get|set|unset` (`src/lib/studio-config.ts`, ключи — `.agents/skills/motion-studio/references/settings.md`): аккаунт по умолчанию или `ask`, язык, шаблон, длительность, фактчекинг, озвучка, порт UI, предел активных задач, слотов рендера (=1, меняется только по словам пользователя), декларация агента. Секретов в файле нет.

## Параллельная очередь (решение пользователя 2026-10-21)
«Единственное, что у нас должно идти не параллельно, это рендер.»
- `JobScheduler` (`src/lib/job-scheduler.ts`) запускает все задачи из очереди сразу, каждую со своим `AbortController`. Предел — `engine.maxActiveJobs` (0 = без предела). `claimJob` не берёт вторую задачу проекта (подборки, анализа стиля), пока идёт первая.
- Отмена (`cancel`, UI), пауза (`pause` → строка задачи `held`, проект `paused`), парковка агента через 60 мин и `PAID_GATE` останавливают только свою задачу; задача следит за своей строкой и проектом раз в секунду. Перезапуск движка возвращает выполнявшиеся задачи в очередь (`running→queued`), задания агента переиспользуются по хешу промпта.
- **Слот рендера** (`src/lib/render-slot.ts`, FIFO, `engine.renderSlots`=1): Remotion `renderMedia`/`renderStill` (включая лист ключевых кадров), `selectComposition`, сборка бандла, кодирование итогового MP4, фоновая музыка и сведение `remix.py`. Пока проект ждёт слот, его этап — «Ждёт слота рендера: сейчас …»; время ожидания и работы в слоте пишется в журнал проекта.
- Вне слота и параллельно: ожидание агента, Tavily, ElevenLabs TTS (короткая конвертация FFmpeg внутри `speech.py` тоже), Scribe, извлечение кадров, OCR, измерение итогового файла.
- Семафоров для API нет. ElevenLabs TTS (`scripts/elevenlabs_speech.py`) и Scribe (`src/lib/author-providers.ts`) при HTTP 429 с признаком лимита/занятости повторяют запрос с backoff 2/4/8/15/30 с (учитывая `Retry-After`); 429 с квотой и прочие ошибки не повторяются. 429 значит «запрос не выполнен», поэтому повтор не оплачивается второй раз: маркер неизвестного платного результата снимается на время ожидания, успешный ответ кэшируется один раз, `PAID_GATE` по-прежнему останавливает новый дубль.
- Легаси- и UI-проекты (GPT‑6.1 Sol / Claude Opus 5.5 через CLI) сохраняют прежний порядок: одна такая задача за раз, их куски ревью кадров — по одному; агентные задачи идут параллельно с ними.
- Ревью кадров итогового MP4 в агентном режиме отдаёт все куски (`frame-review-0/-8/-16…`) сразу; ключи кэша и промпты прежние.

## Как это устроено
1. `npm run studio -- create … --agent …` создаёт проект и ставит обычную задачу `render`.
2. Worker выполняет задачу внутри агентного контекста (`AsyncLocalStorage`, `src/lib/agent-provider.ts`). Любой вызов `askJSON`/`askClaudeJSON`/`contentAsk` в таком контексте становится заданием: `data/projects/<id>/agent-tasks/<NNN-роль>/{prompt.md,schema.json,images/,meta.json}`. Проект получает статус `awaiting-agent`.
3. Worker ждёт ответа **внутри той же задачи** (опрос раз в секунду), поэтому кэши ролей, порядок и бюджет исправлений прежние; повтор промптов не нужен.
4. Агент пишет `answer.json`, `npm run studio -- submit` проверяет его по strict-схеме (`z.fromJSONSchema`), worker применяет `restoreAgentOptionals`, затем обычную смысловую проверку роли. Ответ используется один раз; провалившаяся смысловая проверка порождает новое задание с замечаниями.
5. Без ответа 60 минут задача паркуется (`jobs.status='held'`); другие задачи всё это время идут параллельно. `run`/`resume` возвращают её, висящие задания переиспользуются по хешу промпта. При паузе в агентном режиме источники не просрочиваются через 24 ч, а время аудита не входит в промпты.

## Проверка ключевых кадров до рендера
Практика из подборки «claude-motion»: перед полным рендером агентного проекта worker рендерит 6 ключевых кадров (6/24/42/60/78/95 % длительности) в лист 3×2 с подписанными секундами (`keyframes/<hash>/keyframes-3x2.jpg`) и отдаёт его агенту заданием `keyframe-review` (независимая роль → сабагент). `changes` один раз перестраивает постановку по заметкам без новой озвучки и рендерит уже без повторной проверки; `pass` сохраняется в `keyframe-review.json` по хешу плана. Если пользователь описал ролик брифом, агент кладёт его в `data/projects/<id>/brief.md` — проверка ключевых кадров видит бриф.

## Остановки
- **Платное:** первая озвучка входит в просьбу. Новый платный дубль ElevenLabs после успешного (новый ключ кэша) останавливает задачу `PAID_GATE` → проект `awaiting-user`, `paid-gate.json`. Только после явного «да» пользователя: `confirm <id> tts --quote "…"` (цитата сохраняется в `paid-confirmations.json`). Разбор Reels (Apify Free, предел $1) требует `--user-confirmed`.
- **Одобрение:** только по дословной фразе пользователя: `approve <id> --quote "…"` → `approval.json` (`approvedVia:"agent-chat"`, хеш MP4). Технический pass и ревью модели не одобряют ролик.
- **Правка изображения:** одна автоматическая (как раньше, теперь и для шаблонов с режиссёром) + до двух по заметкам агента (`repair`, job `picture-repair`) на версию речи, без TTS.

## Сессия не заканчивается раньше ролика
- `npm run studio -- run <id> [<id2> …] --timeout 540` блокирует и печатает прогресс; с несколькими id возвращается, как только любому ролику нужен агент (`MOTION_STUDIO_FOCUS=<id>`). Коды выхода: 0 готово, 10 задания, 11 решение пользователя, 12 нужен рендер, 13 на паузе, 20 ещё идёт, 30 движок не запущен, 1 ошибка, 2 остановлено.
- Claude Code: `.claude/settings.json` — PostToolUse(Bash) `scripts/agent-run-hook.mjs` связывает `MOTION_STUDIO_RUN=<id>` с сессией (`data/agent-runs/<session>.json`; запуск из Bash сабагента записывается на сессию ведущего — проверено 2026-10-21); Stop-хук `scripts/agent-stop-hook.mjs` не даёт закончить ход, пока ролики этой сессии `queued/running/awaiting-agent`, и перечисляет все, сначала ждущие агента. Отпускает при `awaiting-user`/`paused`/`review`/`failed`/`cancelled`, после одного напоминания при остановленном движке и после трёх напоминаний без прогресса. Каждая сессия держится только своими роликами. Ошибка хука — не блокирует.
- Codex: CLI 0.163 поддерживает hooks (`Stop`, `stop_hook_active`, `decision`); те же скрипты подключены в `.codex/hooks.json`. Codex может попросить доверить хуки проекта; формат проверен по бинарнику, не реальным прогоном Codex. Правило «не заканчивать до готового ролика» есть и в AGENTS.md.

## Независимость ролей
Задания редактора, фактчека, ревью кадров и фрагментов разборов помечены «сабагент». В Claude Code их выполняет `.claude/agents/studio-role.md` (только Read/Write, без shell), затем `submit --isolated`. Ответ без изоляции записывается как `isolated:false`.

## Шаблоны
`src/lib/video-templates.ts` находит шаблоны на диске: три встроенных — первыми, с прежними версиями и отпечатками (tech-story/v1, model-breakdown/v1, illustrated-scene/v2); сохранённые — старшая версия, `id@vN` — конкретная. Битый шаблон пропускается. `template save` (`src/lib/template-save.ts`) — только из одобренного проекта, только новая папка/версия (эксклюзивная запись), настройки + правила (из снимка базового шаблона или профиля) + эталон (`reference/`) + `provenance.json`. Встроенные id и `tech-story/v1` не перезаписываются. `template sample <style-lab-id>` (`saveStyleSample`, решение пользователя 2026-10-20) сохраняет образец style-lab как шаблон с `styleSample.connected=false`: правила из STYLE.md, эталон, кадры, снимок исходников `reference/source/`, `provenance.json` с дословной просьбой. Сюжет — `work/style-lab/<id>/story.json`, если он есть (иначе общий `work/style-lab/story.json`), постер — `poster` из template-meta (иначе frame-9.0s.png). `createProject` такой шаблон отклоняет, в UI карточка помечена «Образец стиля», в форме создания его нет.

## Несколько роликов
Схемы — `.agents/skills/motion-studio/references/harnesses.md`: одна сессия чата на ролик; ведущий Claude Code + сабагент general-purpose на ролик (у сабагента есть shell и свои сабагенты `studio-role`, проверено 2026-10-21); один агент с `run <id1> <id2> …`.

## Ограничения
- Локальный рендер идёт строго по одному (слот рендера): три ролика, готовые к рендеру одновременно, рендерятся друг за другом.
- Пока агент думает над заданием, его ролик ждёт; другие ролики идут.
- Замер 2026-10-21 (Apple M4, 10 ядер, слот свободен): кодирование FFmpeg итогового MP4 (94 с, 1080×1920) одно — 12,6 с, одновременно с нагрузкой ревью другого ролика (полное декодирование, извлечение кадров, OCR) — 20,3 с (+61 %); само ревью 12,6 → 22,7 с (+80 %). Вместе 22,7 с против 25,2 с подряд: общее время почти то же, но каждый шаг дольше. На полном рендере Remotion одно наблюдение дало около +5 %. Ревью и извлечение кадров по решению пользователя идут вне слота; включать их в слот — только по его решению.
- Ведущий агент видит кадры, а не непрерывное воспроизведение; `humanPlayback=false`.
- `--engine legacy` создаёт проект со встроенными Codex/Claude — только по явной просьбе.
