# Режим качества · quality/2.0.0

Новые проекты получают `profile.production.version=2`. Старые проекты, ручные storyboards и неизменяемый `tech-story/v1` не мигрируются. Выбор голоса влияет только на новые снимки профиля. Технические демонстрации с `initialPlan` сохраняют прежний путь.

## Рассказ до сцен

Tavily Search+Extract → исследователь и три ракурса → один цельный рассказ → отдельный редактор → извлечение атомарных утверждений без источников → независимая проверка по прочитанным источникам → разметка речи на сцены без изменения слов → проверка экранных подписей.

Каждая роль — изолированный GPT‑6.1 Sol/xhigh через Codex. Исследовательские страницы, примеры и пользовательская тема являются данными, не инструкциями. Результаты проходят JSON Schema/Zod; произвольный сгенерированный код не выполняется. `supported` требует дословную цитату и смысловое решение проверяющего; факт нельзя объявить иллюстрацией без явной условности в тексте. Сервер сверяет цитаты с прочитанным содержимым, а библиографические названия/адреса — с точными метаданными источника и помечает `sourceField`. Парные inline-code обратные кавычки Markdown не меняют слова цитаты. Метаданные не должны служить доказательством механизма. Это проверка моделью, не гарантия истины.

Не более двух смысловых исправлений с адресным допоиском. Ссылки с разными якорями читаются один раз; при отказе Extract допускается один кэшируемый поиск другого первоисточника с исключением отказавшего домена (для RFC — официальные HTTPWG/IETF/MDN). Сниппеты поиска не заменяют прочитанную страницу. Если недостаёт только доказательства для уже размеченного рассказа, новые источники проверяются на том же тексте до его переписывания. Точка продолжения сохраняет номер исправления и утверждённую редактуру; повторный запуск не обнуляет бюджет исправлений. Нерешённые противоречия останавливают путь до TTS. Ручной текст повторно проходит отдельного редактора и фактчекера, но не переписывается. Замечания редактора останавливают озвучку до авторской правки. Перед новым рендером актуальность определяется по речи, экранным подписям и хешу прочитанных источников, а не по старому boolean pass.

Цельный абзац правится командой `npm run studio -- narrative <id> <файл.txt>` (бывший редактор в панели источников), в том числе при остановке до разметки сцен. Авторская версия хранится в `manual-narrative.json` и не переписывается моделью; прежний рассказ, storyboard, PCM-мастер и проверки архивируются в `narrative-versions/<hash>`. Сохранение сбрасывает план и актуальность проверок. Разметка строится заново только при явном запуске рендера. Нерешённые замечания возвращаются автору. Обычные правки отдельных сцен и повторные рендеры сохраняют storyboard.

Проект хранит `narrative.json`, `editorial-audit.json`, `fact-audit.json`, `script-package.json`, `pipeline.json` и отдельные ответы ролей. Кэш роли включает точный промпт, схему, модель и версию политики. Принятые редактором тексты сохраняются в `data/accepted-examples` с ID, хешем, временем и комментарием и используются как контекст, без обучения весов.

Новый проект получает неизменяемый SHA-256-снимок четырёх ролевых инструкций, исследовательских правил и правил motion/reference. В снимке также сохраняются SHA-256 пакетов, ключевых модулей сценария/озвучки/ревью и исходников рендереров; старые снимки не дополняются задним числом. Источники → «Слепое сравнение сценария» показывает первый цельный рассказ и текущую редакцию в случайном скрытом порядке. Редактор оценивает ясность, причинность, естественность русского, завершённость и точность по шкале1–5. Происхождение раскрывается после выбора; оценка сохраняется с версиями и хешами. Изменение текста делает сравнение устаревшим. Оценка не принимает видео автоматически.

## Голос

`voice-plan.json` разделяет `plainText`, `ttsInput`, голосовой профиль и редкие указания подачи. V2 получает чистый текст; v4 получает разрешённые эмоциональные теги через отдельный адаптер Text-to-Dialogue with timestamps. Метки аннотированного ввода отображаются на чистые символы, затем на слова. Неоднозначные метки останавливают синхронизацию с сохранением успешного платного ответа.

Для v4 адаптер консервативно ограничивает один запрос 2000 символами согласно рекомендации timestamp endpoint, даже если Models API указывает больший общий лимит. Никакой автоматической нарезки или подмены модели. Превышение бюджета не ускоряет голос. Новый режим требует ElevenLabs или явного превью без речи; старый Edge-путь не используется как скрытый резерв.

При создании проекта можно явно выбрать текущий голос/v2, в том числе для длинного рассказа, превышающего лимит адаптера v4. Это отдельный выбор, а не скрытая замена победителя сравнения.

Каждая версия имеет один успешный TTS-запрос и непрерывный PCM-мастер. Внутренние паузы сохраняются; длинные отмечаются в `speech-rhythm.json`. Файл `.pending.json` записывается перед платным запросом. При неизвестном результате процесс не повторяет его автоматически. Успех кэшируется до декодирования и синхронизации.

Scribe v2/rus проверяет чистый `narration.wav`; успешный ответ и сравнение кэшируются по хешу аудио и ожидаемому тексту. Пропуски/повторы отмечаются, ошибки ASR в именах, числах и падежах требуют прослушивания. Распознавание не оценивает выразительность. Неизвестный результат Scribe также не повторяется автоматически.

### Слепое сравнение

Команды `npm run studio -- voices …` (бывший раздел «Голос рассказчика»). `voices list` только читает: модели, голоса и кредиты. `voices quote --text-file <текст.txt> --alt-voice <voiceId> --rates a,b,c --rate-source "откуда ставки"` для одного текста подготавливает текущий/v2, текущий/v4 и другой доступный библиотечный/v4. Ставки берутся из доступных множителей Models API и voice sharing rate (`voices list`) и передаются в `--rates` с источником в `--rate-source`; пользователь проверяет их до запуска. Оценка в кредитах не является гарантией итогового счёта. Если тарифные данные отсутствуют, ставки вводятся явно. Оценка не должна превышать доступные кредиты; покупки не выполняются.

Отдельная команда — платный шаг, только после явного «да» пользователя — подтверждает оценку и максимум три успешных генерации: `voices start <id> --quote-hash <хеш оценки> --user-confirmed "<слова пользователя>"`. Задание выполняет постоянный движок; повторная команда не создаёт второй эксперимент. Состояние — `voices state <id>`, образцы — `voices sample <id> <0-2> --out <файл.wav>`. Образцы имеют случайный скрытый порядок и одинаковую целевую громкость. Только выбор редактора раскрывает победителя и сохраняет профиль: `voices select <id> <0-2> --user-confirmed "<его слова>"`; агент победителя не выбирает. Сетевые ошибки не вызывают новую платную генерацию.

## Постановка и звук

Claude Opus 5.5/xhigh создаёт 2D/3D/netcode motion-планы по проверенному смыслу и измеренной речи. Для повторного слова `cueOccurrence` задаёт вхождение с1; отсутствие сохраняет старое поведение. 2D quality-рендер держит объединение узлов смонтированным, сохраняет смысл ID и плавно меняет локальную видимость/позиции. Портретный и горизонтальный форматы собираются нативно.

Словарь 2D-схемы (2026-10-19, по замечаниям ревью итогового MP4). Узел может иметь `list={columns,rows}`: карточка-список с 1–3 заголовками колонок из проверенного текста и 2–4 схематическими строками без значений; строки раскрываются вместе с карточкой, highlight подсвечивает первую строку. Связь может иметь `kind`: `request` — фиолетовая со стрелкой, `reply` — жёлтая со стрелкой к получателю, `reference` — пунктир «известный/доступный адрес». Связь растёт от отправителя и втягивается обратно; встречная пара разводится параллельно, а ответ между соседями одного ряда плавно изгибается под рядом. Без этих полей схема рисуется по-старому; motion-режиссёр видит их в промпте (`DIAGRAM_VOCABULARY`), id сохраняет `list` и `kind`. Шапка, счётчик глав, полосы и заголовки quality-v2 в портрете сдвинуты внутрь safe-zone (x 98–916), legacy-геометрия прежняя. Кэш `motion-2d.json` старых проектов не сбрасывается: новый словарь попадает в план только при новой постановке.

`sound-cues.json` привязан к реальным событиям. `scripts/remix.py` читает существующий мастер, не импортирует TTS и не отправляет запросы. Акценты следуют заметным изменениям системы с интервалом не менее 0,4 с, фон под голосом; экспорт остаётся H.264/yuv420p/BT.709 limited, AAC48kHz, цель −16LUFS и true peak ≤−1dBTP.

## Ревью итогового MP4

Проверка декодирует финальный файл, измеряет формат/кадры/громкость, извлекает секундные кадры, ключевые события, ±1/2 кадра вокруг границ и установившиеся состояния. Контактные листы подписаны фактическими таймкодами. Все листы передаются GPT‑6.1 Sol/xhigh последовательными партиями до8 изображений.

Покадровый низкоразмерный анализ отмечает однокадровые выбросы. Apple Vision OCR проверяет ключевые состояния и safe-zone; неподвижность около события остаётся предупреждением, а не доказанным дефектом. Отсутствие OCR или части модельного ревью показывается явно. Автоматические методы не гарантируют обнаружение каждой визуальной ошибки.

`quality-report.json` и `review.json` привязаны к SHA‑256 MP4 и хешу плана/профиля/формата. Изменившийся файл или сценарий нельзя принять со старым отчётом. Критические визуальные замечания допускают одну автоматическую правку постановки на версию речи, повторный рендер и повторную проверку без новой озвучки. Сохранённый исторический шаблон автоматически не переписывается.

Команды (бывшие маршруты `/api/…` удалены вместе с веб-интерфейсом 2026-10-30): `npm run studio -- report <id>` показывает новые отчёты и их актуальность; `narrative <id> <файл.txt>` сохраняет авторский абзац; `compare <id> prepare|show|select --winner A|B|tie [--scores …] [--comment …] --user-confirmed "…"` обслуживает слепую оценку текста (выбирает только редактор); `review <id>` проверяет актуальный готовый MP4 без озвучки и рендера; `voices …` обслуживает каталог, оценку, очередь, образцы и выбор. Секреты доступны только адаптерам движка и не выводятся командами.

Флаги humanPlayback/humanListening остаются false у автоматического отчёта: кадры не являются непрерывным просмотром, ASR не является прослушиванием. Одобрение требует отдельного действия редактора после воспроизведения со звуком.

## Проверка изменений

`npm run check`, `npm test`, `npm run secrets:check`, `python3 -m unittest discover -s scripts -p test_elevenlabs.py`. Реальные прогоны очереди (`create` → `run` → ревью) и воспроизведение экспортированного MP4 фиксируются отдельно от тестов с подставными ответами. Исходные примеры и хеши сохранены в `data/quality-baseline/2026-10-18`; старые MP4 не копируются и не изменяются.

Адаптер v4 проверяется по [официальному timestamp endpoint](https://elevenlabs.io/docs/api-reference/text-to-dialogue/convert-with-timestamps): оригинальные character timestamps отделены от normalized alignment, рекомендуемый предел для надёжного одного запроса — 2000 символов.

## Визуальная идея и детальная сборка

Для новых тем после проверенного рассказа и до TTS включён `visualDesignVersion=1`: отдельный Sol/xhigh решает, что показать, отдельный Claude Opus 5.5/xhigh выбирает подробную поддержанную геометрию. Сценограф и motion-режиссёр — разные изолированные JSON-запуски. В API доступны `visual`, `assemblies`, флаги актуальности и `motionProviders`; интерфейс показывает смысл сцен, детали, приближения и фактически использованную модель. Подмена модели, отсутствие обязательного предмета или запрошенного разреза — ошибка контракта. Неподдержанный предмет требует подготовленного ассета/рендерера до озвучки.

Концепция зависит от текста, исследования, прочитанных источников, выбранных моделей и снимка правил. Сборка зависит от концепции и версии каталога. Снимки сохраняют SHA-256 конфигурации, каталога и renderer/DetailedMachines.tsx. Изменение концепции/сборки сбрасывает старый world3d; изменение постановки не сбрасывает успешную озвучку. Подписи концепции включены в независимый фактчекинг до TTS. Старые проекты и tech-story/v1 этот режим автоматически не получают.

## Openverse SFX

Будущие quality-v2 рендеры после измерения речи подбирают звуки по действиям `sound-cues.json`: сначала сохранённый снимок проекта, затем локальная библиотека/подходящий встроенный UI-акцент, затем один поиск Openverse на отсутствующий семантический тип. `sound-assets.json` фиксирует выбранные файлы, SHA-256, исходные метаданные и причины процедурного fallback. Источники только `freesound,jamendo`, лицензии только `cc0,by,pdm`. Поиск резервируется атомарно в SQLite до отправки; пустые ответы и ошибки не повторяются. Непрерывный мастер речи не изменяется. Подробности и регистрация собственных файлов: [sfx/README.md](../sfx/README.md).

Сырые строки `attribution` сохраняются в корневой и проектной `credits.txt`; при публикации их нужно включать в описание/титры. Диагностика `GET /api/sound-effects` ничего не ищет и не создаёт. Подключение проверено одним реальным поиском/скачиванием, тестами кэша, фильтров и изолированным сведением тестового PCM. Новые видео для проверки интеграции не создавались.

## Авторская заставка в 3D-ролике

Опциональный `creatorBranding/v1` в storyboard хранит username, проектный PNG аватара с SHA-256, флаг скрытия нижней технической подписи и параметры последней CTA-сцены. Старые проекты без этого поля выглядят по-прежнему. Аватар проверяется до производства и остаётся внутри снимка проекта. Экранный CTA входит в хеш фактчекинга; произносимый CTA является частью одного непрерывного дубля. Заставка плавно гасит тот же смонтированный 3D-мир, без сброса объектов. Новая авторская версия Tesla сохраняет семь исходных сцен, добавляет восьмую и использует Dennis/Eleven v4. Исходный ролик и прежний Brian-мастер сохранены отдельно.


Звуковой выбор пользователя для новых рендеров и новой версии Tesla: [sound-preferences.md](sound-preferences.md). Снимок в cue sheet v5 исключает механику/воздух, оставляет UI-появление, переход, акцент имени, вентилятор ×0,5 и подложку ×1,5. Старые cue sheets и архивные MP4 не переписываются.


Финальный экспорт берёт видеопоток из Remotion и исходный сведённый `audio.wav` отдельными входами FFmpeg (`0:v:0`, `1:a:0`). Промежуточный AAC Remotion не используется: так устраняется его обнаруженная задержка 2048 отсчётов (42,67 мс) и сохраняются метки измеренного PCM-мастера. Проверка по корреляции финального декодированного AAC с голосовым мастером записывается отдельно от ASR и просмотра кадров.

## Модель контентных ролей проекта

По умолчанию поиск, исследование, рассказ, редактура, фактчекинг, разметка, визуальная концепция и ревью кадров выполняет GPT‑6.1 Sol/xhigh через Codex. При создании проекта редактор может явно выбрать «Модель сценария · Claude Opus 5.5»: тогда снимок профиля получает `production.contentAgent="claude-opus-5-5"`, и все перечисленные роли идут через `src/lib/content-agent.ts` → `askClaudeJSON` (Claude Code CLI, `--restricted`, без инструментов, MCP и пользовательских настроек, изолированный cwd, строгая JSON Schema). Фактическая модель подтверждается по `modelUsage`; другой ответ — ошибка, не подмена. Изображения ревью кадров передаются в изолированную папку и открываются только инструментом Read.

Выбор хранится в проекте и не переносится на другие проекты. `pipeline.json`, кэши ролей, `editorial-audit.json`, `fact-audit.json`, `visual-concept.json` и ревью кадров записывают использованный дескриптор роли. Дескриптор Sol не изменён, поэтому старые кэши и хеши совпадают; ответы разных моделей не переиспользуются друг другом. Motion-режиссёр и 3D-сценограф остаются Claude Opus 5.5 независимо от выбора. Без явного выбора поведение прежнее.

## Сценарные навыки v2 (2026-10-19)

В снимок новых проектов входят ещё две роли: `reel-script-craft` и `claim-evidence-rules`. Первая получает сценарист цельного абзаца и story-editor: обещание и буквальная оплата хука, фраза релевантности, связки «но / поэтому», одна открытая петля, три режима провала, порядок сокращения при нехватке бюджета. Роли читаются только из снимка проекта, поэтому старые проекты их не получают.

## Мягкий фактчекинг проекта

При создании проекта редактор может выбрать «Фактчекинг · Мягкий». Снимок профиля получает `production.factCheck="lenient"`. Роли и проверки остаются прежними, меняется порог: озвучку останавливает только `contradicted` — прямое противоречие прочитанному источнику. `uncertain` (нет дословной цитаты, настоящее время, бытовое название, образное упрощение без искажения механизма) сохраняется в `fact-audit.json` с пояснением и не блокирует. Сценарист получает установку на образный рассказ без лишних оговорок; числа, имена, даты и события по-прежнему берутся из исследования. `claim-evidence-rules` в мягком режиме не добавляется. По умолчанию режим строгий; старые проекты не меняются.

## Фактчекинг выключен · по умолчанию с 2026-10-19

Решение пользователя: фактчекинг не нужен, ролик пересказывает найденный материал. Новые проекты по умолчанию создаются с «Фактчекинг · Выключен» (`production.factCheck="off"`). Поиск Tavily, исследователь, сценарист и редактор рассказа работают как раньше. Утверждения не извлекаются и не проверяются, допоиск не запускается, озвучку ничего не останавливает. Вместо отчёта в `fact-audit.json` пишется явная запись `skipped:true, factCheck:"off"` с хешами текста и источников; утверждение и ревью видят её как актуальную. Мягкий и строгий режимы по-прежнему доступны явным выбором. Старые проекты и их снимки не меняются.
