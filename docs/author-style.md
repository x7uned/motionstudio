# Как будем настраивать стиль автора

## Первый проход: дизайн

Сначала соберём несколько кадров разных сцен. Для каждого отметим палитру, расположение заголовков, плотность текста, визуальные акценты, фон, размеры элементов и характер иллюстраций. Отдельно отличим постоянные приёмы от особенностей одного ролика. Студия принимает материалы (`npm run studio -- style refs add <кадры.jpg|png|webp|txt|srt|vtt>…` или `style refs add --text-file <файл> --name «…»`; список — `style refs list`, убрать/вернуть — `style refs archive|restore <id>`), извлекает правила (`style analyze --agent «<среда/модель>»`) и сохраняет редактируемый профиль (`profile get --out <файл>`, `profile set <файл>`).

В текущем рендерере автоматически применяются фон, цвет текста, акцент и шрифт Manrope/Inter. Правила подачи помогают выбирать структуру и типы сцен. Если в референсах будут, например, бумажные коллажи, собственная типографика или конкретный вид диаграмм, создадим для них проверяемые шаблоны в коде. Так точные надписи и тайминг останутся редактируемыми.

## Второй проход: сценарии

Для каждого транскрипта полезно сохранить тему, аудиторию, финальный текст и сведения, что именно в нём нравится. Будем отмечать:

- чем автор цепляет в первой фразе;
- сколько идей объясняет и в какой последовательности;
- как вводит термин и какую аналогию выбирает;
- длину фраз, разговорные обороты и ритм;
- где создаёт контраст или возвращается к исходному вопросу;
- как заканчивает объяснение.

Примеры служат опорой для структуры, а не командой копировать конкретные фразы. Материалы автора пока не предоставлены, поэтому базовый профиль не выдаётся за его стиль.

## Третий проход: проверка на новых темах

Составим небольшой фиксированный набор тем, не встречавшихся среди примеров. Сравним сценарии по пяти критериям: понятность, точность, узнаваемость подачи, укладывание в хронометраж и соответствие визуалу. Для каждого замечания сохраняем до/после и причину принятия.

Если правила и подобранные примеры дают стабильный результат, достаточно этого подхода. Если остаётся повторяемая ошибка, сначала исправим контекст и шаблон. Дообучение можно оценивать позже на накопленном наборе одобренных пар, отдельно проверив доступность подходящего провайдера и права на материалы. Команды обучения модели в студии нет.

## Данные уже подготовлены для этого процесса

Каждый проект хранит сценарий JSON, профиль на момент создания, контекст генерации, измерения аудио/видео, автоматическую критику и решение редактора с комментарием. Это основа будущего набора примеров и оценок. Для следующего этапа можно добавить экспорт принятых примеров, версионирование нескольких профилей и сравнение двух вариантов сценария.
