# Каталог Kagenami · пополняем, пока делаем видео

Решение пользователя (2026-10-28): «если мы отрисовываем какие-то ассеты, и они получились хорошо, то добавляем их в наш каталог в Kagenami… чтобы мы как раз дополняли наш каталог, пока делаем видео». Это обычный шаг каждого ролика, отдельно не спрашивай. Общение — по-русски.

## Где каталог
- Корень: `/Users/rv/Desktop/kagenami/packages/pixel-engine/catalog` (дальше `catalog/`).
- Рабочий набор — **init**: `catalog/init/assets/<kind>.mjs` (объекты), `catalog/init/backdrops/<kind>.mjs` (фоны), помощники `catalog/init/lib/`, реестр `catalog/init/manifest.json`, листы `catalog/init/sheets/`, галереи `catalog/init/gallery/`, отчёты `catalog/init/reports/`. Загрузчик (`catalog/items/index.mjs`) сам подхватывает любой новый файл из `init/assets` и `init/backdrops`.
- Контракт предмета и фона: `catalog/items/README.md` (kind, covers, desc, hw/hh, start, states 2–6, base, st, linear, чистый `draw`, `{box, pt}`; фон — `backdrop: true`, theme, `draw(c, cam, t)`). Стиль и состав: `catalog/init/BRIEF.md` §4 (один ассет = один объект, 3–6 состояний, без текста, кроме `s.label`/`s.value`; у фонов спокойная середина y 262–440, пол y 540–580, кадр заполнен при зуме 1–2,4).
- Старый набор v1 (`catalog/items/*.mjs`) — только для чтения.

## Когда добавлять (все условия)
1. Ассет нарисован **нами** для ролика и прошёл в ролике, который сдал QA финального MP4 (или пользователь прямо сказал «добавь»). Не ждём одобрения ролика: в каталоге он тоже «не одобрен».
2. Он **хорош**: на листе читается с одного взгляда на телефоне, в стиле дома (тёмный контур 1 px, свет сверху слева, ступени цвета + Bayer, без сглаживания и размытия), не хуже соседей в `init/gallery/`.
3. Он **переиспользуем**: обычный объект или место, полезное и в других темах (планета, телескоп, гора), либо узнаваемый тематический объект надолго (Плутон). Одноразовые сцены, монтажные связки, графики с цифрами конкретного ролика — не добавляем.
4. Можно по правилам: без логотипов, брендов, реальных людей, игровой IP, флагов как бренда (флаг страны — только наш рисунок общедоступного рисунка), без героя канала (коралловый пуховик, фиолетовая шапка) и аватара/спрайтов `data/branding/`.
5. Kind ещё не занят в init. Занят — не перезаписывай: возьми точное имя (`ice-world`, `pluto-heart`) или спроси пользователя, заменить ли старый. Существующие файлы каталога не меняются без слов пользователя.

## Как добавлять
Работай только в `catalog/init/` новыми файлами + дописывай `manifest.json` и свой отчёт. Не трогай `engine/`, `tools/`, `contract.mjs`, `items/`, чужие ассеты. Без git-коммитов, без рендера видео, без сети.

1. **Отбор.** По отчёту сборщика и кадрам ролика составь список: kind → файл фильма → почему годится. Сомнительное не бери (сначала правка в фильме, потом каталог).
2. **Копия, не ссылка.** Скопируй код из папки фильма в каталог (из фильма в каталог никогда не импортируем — папки фильмов меняются):
   - объект → `catalog/init/assets/<kind>.mjs`; фон → `catalog/init/backdrops/<kind>.mjs`;
   - общий код → `catalog/init/lib/film-<папка-фильма>-<имя>.mjs`;
   - шапка файла: `// Kagenami catalog init · from work/pixel-lab/<film>/film/<file> (YYYY-MM-DD); changes: …`;
   - пути: raster `../../../renderer/pixel/raster.mjs`, движок `../../engine/layout.mjs`, свои lib `../lib/<file>.mjs`, cute/shade v1 `../../items/lib/…`;
   - если файл фильма побайтно совпадает с уже лежащим в каталоге (`engine/layout.mjs`, `init/lib/space-kit.mjs`, `init/lib/bd1-kit.mjs`, raster), импортируй существующий, а не копируй (`cmp`);
   - фон, который импортирует другой фон фильма (например, гора берёт небо из Млечного Пути): общий код — в один `init/lib/film-<film>-<имя>.mjs`, оба фона импортируют его; переноси их вместе и только после всех правок картинки в фильме (иначе в каталог уедет старая версия);
   - в объекте `source: "film <film> (new)"`, `covers: [kind, …английские синонимы]`, `desc` ≤ 20 слов (его читает модель-режиссёр).
3. **Под контракт.** Позы и режимы фильма → 2–6 именованных состояний (первое — покой). Всё через `s.v`, `s.acc`, `s.a`; никаких переключений за кадр, `Math.random`, часов. Убери из объекта всё, что не он сам (фон, подписи, второй предмет).
4. **Проверка листом** (из `catalog/`):
   ```sh
   CATALOG_SET=init node tools/sheet.mjs --small <kind>     # состояния + проверки
   CATALOG_SET=init node tools/sheet.mjs <kind>             # финально: с переходами
   ```
   Открой `init/sheets/<kind>.png` и посмотри. Готово: объект — `jumps 0 · pops 0 · pure true · footprint ok`, ≤ 25 мс/кадр; фон — `jumps 0 · pops 0 · pure true`, ≤ 40 мс/кадр, плюс `node init/edge-check.mjs` (кадр заполнен при любой камере). Время сверяй по чистой отрисовке: `node init/edge-check.mjs` для фонов и `node init/time-assets.mjs` для объектов; мс из `sheet.mjs` включают накладные расходы листа и бывают в 2 раза выше. Мелкий флаг допустим только с причиной в `notes`. Не больше 3–4 просмотров листа на ассет.
5. **Реестр.** Допиши в `init/manifest.json` (порядок и старые записи не трогай) записи с продолжением нумерации — скриптом (`python3`: `json.load` → `append` → `json.dumps(m, ensure_ascii=False, indent=1) + "\n"`), не ручной правкой, чтобы не сломать формат:
   ```json
   {"n": 101, "kind": "pluto", "ru": "Плутон", "file": "assets/pluto.mjs", "group": "film:ed138", "added": "2026-10-28", "from": "work/pixel-lab/ed138/film/assets/pluto.mjs", "status": "not approved"}
   ```
   Номера: assets — после последнего `n` в `assets`, backdrops — после последнего в `backdrops`.
6. **Галерея и отчёт.**
   - `CATALOG_SET=init node tools/contact.mjs --first=1 --only=<kind,kind…> --out=gallery/film-<film>` → контактный лист новых позиций;
   - строка на ассет в `init/reports/films.md`: `n · kind · from <film> · states · check line · заметки`;
   - `CATALOG_SET=init node init/status.mjs` — все новые позиции `loaded OK` (итоги «/30 · /100» в его последней строке зашиты в инструмент; с новыми позициями там будет больше — это нормально).
7. **Пользователю** — коротко: что добавлено (kind, состояния), где лист/галерея, что не взяли и почему. Каталог init пока не подключён к генерации роликов (`CATALOG_SET=init` только для инструментов) — так и скажи, не «подключено».

## Для сборщиков фильмов
Чтобы перенос был дешёвым, в брифе сборщика проси рисовать каждый новый объект отдельным модулем `film/assets/<kind>.mjs` сразу в контракте каталога (чистый `draw(c, cx, cy, z, t, s)`, состояния), а фильм ведёт их через маленький адаптер `s`. Фоны — `film/assets/backdrop-<kind>.mjs` с `backdrop: true`, где это не дорого. Сам сборщик в каталог не пишет: перенос делает ведущий (или отдельный сабагент с этим скиллом) после QA ролика.

## Запреты
- Не перезаписывай и не правь существующие ассеты каталога, `manifest`-записи 1–130, v1 `items/`, движок и инструменты без слов пользователя.
- Не помечай ассеты одобренными: одобряет только пользователь.
- Не копируй в каталог ключи, медиа с чужими правами, реальные снимки, логотипы.
- Не говори «модель обучили на каталоге» — каталог это подготовленные рисунки, которые режиссёр выбирает по описанию.
