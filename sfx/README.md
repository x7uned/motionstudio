# Sound library

Встроенные UI-акценты уже синтезируются локально. Для недостающих предметных звуков подключён Openverse, без ключа и покупок.

`catalog.json` позволяет зарегистрировать существующий подходящий файл: `type` из `EFFECTS` в `src/lib/sound-effects.ts`, `file` внутри `sfx/`, `license` (`original` для собственного звука либо `cc0`, `by`, `pdm`), точный `attribution`. WAV: PCM16, mono, 48 kHz, до 3 секунд. Указывайте тип действия, а не название проекта.

Скачанные исходники, WAV для сведения и исходные метаданные сохраняются в `openverse/<type>/`. Их не нужно переносить вручную: будущий worker создаёт снимок используемых WAV и `sound-assets.json` внутри проекта. Атрибуция сохраняется без изменений в корневой `credits.txt` и `credits.txt` проекта. Перед публикацией CC BY звуков включите эти сведения в описание/титры.

Поиск: `https://api.openverse.org/v1/audio/`, `license=cc0,by,pdm`, `source=freesound,jamendo`, одна страница из 20 результатов. Ответ дополнительно фильтруется по этим значениям, длительности, размеру и пригодности к действию; музыкальные и голосовые результаты исключаются. Подбор по названию и тегам не заменяет прослушивание редактором.

Одна попытка поиска на семантический тип сохраняется **до HTTP-запроса** в `data/studio.sqlite` (`sound_searches`). Пустой ответ, ошибка, HTTP429 или неизвестный исход не запускают новый поиск. Локальный потолок 200 поисков в UTC-сутки; ограничение Openverse может включать другие приложения с того же IP. Новые типы добавляйте в код явно, не переименовывайте существующие ради повторного поиска.

Скачивание выполняет `curl`: публичный HTTPS, проверка и фиксация DNS на каждом редиректе, ограничения времени и размера. Затем ffmpeg создаёт короткий WAV. Голос, API озвучки и исходный PCM-мастер не затрагиваются. Неподходящий/недоступный звук заменяется прежним процедурным акцентом с причиной в отчёте и журнале задания.

Диагностика без поисков: `npm run sfx -- status` или `GET /api/sound-effects`. Явная подготовка одного типа без создания видео: `npm run sfx -- prepare servo-motor`. Обычные будущие quality-v2 рендеры подключают библиотеку автоматически.

## Слышимость · cue sheet v3

Новые планы используют калибровку по активному RMS с мягким ограничением пиков. Это сохраняет слышимость мотора/шума даже при одиночном громком щелчке в исходнике; нормализация только по пику раньше почти заглушала такие записи. Цели до общего мастеринга: сервопривод −24 dBFS RMS, воздух −26, вентилятор −27, переход −22, акцент −25. Пределы пиков отдельны, голосовой мастер не изменяется. `sound-mix-report.json` показывает фактические RMS, пики и усиление каждого события; `sfx-only.wav` позволяет проверить эффекты отдельно. Старые cue sheets без новых полей сохраняют прежнюю обработку.

Если Openverse уже вернул пустой поиск `soft-whoosh`, новый запрос не отправляется: используется локальный детерминированный шумовой переход. При выключении вентилятора не воспроизводится звук его запуска; закрытие корпуса получает механический акцент.

В v3 громкость задают `targetRmsDbFS` и `peakDbFS`. Поле `gain` сохраняется для совместимости и сравнения с прежней обработкой; при наличии целевого RMS оно не служит регулятором громкости.


## Выбор пользователя · cue sheet v5

Текущие настройки и исключения: [docs/sound-preferences.md](../docs/sound-preferences.md). Новые рендеры используют только UI-появление, переход, тональный акцент и вентилятор. Вентилятор ×0,5 после калибровки; фон ×1,5. Переходы также ×0,5; хвост вентилятора 0,9 с, остальные акценты имеют короткое плавное затухание. Изменения системы озвучиваются чаще, с объединением близких событий. Описание v3 выше относится к прежним миксам, а не к текущим предпочтениям.
